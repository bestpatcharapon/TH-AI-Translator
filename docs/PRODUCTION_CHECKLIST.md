# Production readiness checklist

## ก่อน deploy

- รัน Python tests, lint/format, frontend checks, typecheck และ browser regressions ตาม DEVELOPMENT.md
- ตั้ง API keys ใน secrets ของโฮสต์ ไม่ใส่ใน repository หรือ browser
- ตั้ง provider spending limits/alerts และ edge WAF/rate limiting; ตัวนับในแอปแยกต่อโปรเซส/instance ไม่ใช่โควตารวม
- ตรวจ runtime, memory และ execution timeout จริงของแพ็กเกจโฮสต์ เทียบกับงบเวลางานรูป
- เปิด `REQUEST_LOG_ENABLED=1` เมื่อจําเป็น ตรวจ JSON logs และ retention โดยไม่เพิ่มข้อความผู้ใช้หรือไฟล์ลง log; proxy/access/error logs ต้องตรวจแยก

## Smoke test บน staging

ใช้ข้อมูลสังเคราะห์ที่ไม่มีข้อมูลส่วนบุคคล เริ่มจากงานจํานวนน้อยและเพิ่มโหลดทีละขั้น ตั้ง stop condition ก่อนเริ่ม เช่น error rate หรือค่าใช้จ่ายเกินงบ ห้ามยิงโหลดใส่ production โดยไม่มีแผน

- ข้อความสั้น/ยาว, source=auto, ข้อความภาษาเดียวกัน และภาษา RTL
- ภาพข้อความหนาแน่น ภาพอ่านไม่ชัด และจํานวนเกินงบ: ต้องแสดง review/ข้อผิดพลาด ไม่แสดงว่าผ่านทั้งหมด
- PDF สแกน, DOCX และไฟล์เสียหาย ต้องตอบข้อผิดพลาดที่เข้าใจได้
- การยกเลิก/เปลี่ยนโหมดระหว่างรอ ต้องไม่แสดงผลข้ามฟีเจอร์
- ผู้ให้บริการตอบ 429/timeout: ตรวจ Retry-After, การลองใหม่ที่มีขอบเขต และ request ID
- ดู latency p50/p95, HTTP status, cache hit และจํานวนงานพร้อมกันจากข้อมูลจริง; ยังไม่กําหนดความจุผู้ใช้จากผล unit tests

## PWA และฟอนต์บนอุปกรณ์จริง

- ติดตั้งบนมือถือ เปิดครั้งแรกออนไลน์ จากนั้นออฟไลน์: app shell เปิดได้ แต่ต้องไม่แสดงว่า AI แปลออฟไลน์ได้
- กลับออนไลน์และอัปเดต deployment ตรวจว่าหน้า/สคริปต์ไม่ค้างคนละเวอร์ชัน
- ตรวจ cache ของแอปอื่นบน origin เดียวกันไม่ถูกลบ และ API เนื้อหาส่วนตัวไม่ถูก service worker เก็บ
- ตรวจไทย จีน ญี่ปุ่น เกาหลี อาหรับ และภาษาที่กลุ่มผู้ใช้ใช้จริง ฟอนต์ system fallback อาจต่างกันตามอุปกรณ์

## วัดคุณภาพจริง

มี workflow ปิดตาอยู่แล้วที่ `reports/blind-evaluation/README.md` และสื่อจริงที่ `data/real-media/README.md` **ยังไม่ถือว่าประเมินรอบใหม่สําเร็จเพียงเพราะชุดทดสอบผ่าน**

1. ให้ผู้ประเมินที่อ่านคู่ภาษานั้นได้จริงเตรียมโจทย์ holdout ใหม่ที่ไม่ใช้ปรับ prompts/กฎ แยกทั่วไป, ภาษาถิ่น, ตัวเลข/หน่วย, ปฏิเสธ/เงื่อนไข และความกํากวม
2. ตรึง revision, model/config และวันเวลา รันเก็บคําตอบเมื่ออนุมัติงบแล้วเท่านั้น คําสั่ง `--live` ใช้โควตาและส่งตัวอย่างไปผู้ให้บริการ; การเปรียบเทียบ Google ส่งข้อมูลไป Google เพิ่มด้วย
3. ใช้ `scripts/blind_evaluation.py prepare` ซ่อนระบบ A/B และให้ผู้ประเมินกรอกแยกกัน เก็บ key/results ห่างจากผู้ประเมิน
4. รายงานทั้งคําตอบผิด/ขาด, ความหมายผิดร้ายแรง, ความเห็นผู้ประเมิน และ latency อย่ารายงานเฉพาะผู้ชนะหรือรวมทุกภาษาเป็นเปอร์เซ็นต์แม่นยําเดียว
5. เคสที่นํามาแก้ระบบแล้วให้ย้ายเป็น regression set และใช้ holdout ใหม่ในการวัดรอบถัดไป ข้อมูลยา/สุขภาพต้องมีผู้เชี่ยวชาญตรวจ ไม่ใช้คําแปลเป็นคําแนะนําทางการแพทย์โดยลําพัง
