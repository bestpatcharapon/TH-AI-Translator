# ผลปรับคุณภาพการแปลตามบริบท

ปรับจากข้อผิดพลาดที่พบจริงใน [ชุดก่อนแก้](../slang-100/README.md)
และทดสอบด้วยบริการ AI จริงผ่าน `/api/translate` วันที่ 24 ตุลาคม 2026
ใช้ไทย → อังกฤษ โหมด Standard โทน natural และข้าม result cache
ไม่มีการเพิ่มคีย์ เปลี่ยนโมเดล หรือแทนประโยคทั้งประโยคด้วยคำแปลตายตัว

## รอบเต็ม 100 ประโยคสแลงและภาษาพูด

| รอบ | ความหมายใช้ได้ | ควรปรับรายละเอียด/ภาษา | ความหมายหลักผิด |
|---|---:|---:|---:|
| ก่อนปรับ | 67 | 15 | 18 |
| หลังปรับรอบใหญ่ | 91 | 6 | 3 |

ประโยคความหมายตรงตัวอีก 12 ประโยค: ก่อนปรับใช้ได้ 11 ผิด 1;
หลังปรับรอบใหญ่ใช้ได้ 12 ไม่มีข้อผิดพลาดหลักที่ผู้ช่วยตรวจพบ

ตัวเลขเป็นการประเมินของผู้ช่วยเขียนโค้ด ไม่ใช่คะแนนความแม่นยำทั่วไปหรือการให้คะแนน
แบบ blind โดยเจ้าของภาษา รายการนี้มีตัวอย่างที่ใช้ปรับข้อมูลอ้างอิงแล้ว จึงเป็น
regression set การอ่านว่าใช้ได้ไม่ได้หมายความว่าทุกถ้อยคำสมบูรณ์แบบ

ตัวอย่างที่กลับมาถูก: ของแทร่ → the real deal, เมพ → seriously godlike,
สับบนเวที → owned it, กินขาดเรื่องแบต → battery is unbeatable,
ช็อตฟีล → killed the vibe, ด้อม → fandom, เมน → bias,
ทัวร์ลง → got slammed online, ป้ายยาแผล → applied medication to the wound

สามข้อผิดพลาดที่เหลือในรอบเต็มเกี่ยวกับการละประธาน/บอกให้พัก และความตั้งใจ
คบจริงจัง จึงปรับบริบทและทดสอบซ้ำเฉพาะเคสใน `refinement.json`
ไม่ได้นับผลเฉพาะเคสเหล่านั้นแทนการรันเต็ม 112 ประโยคอีกครั้ง

## ประโยคใหม่และการปรับต่อ

`new-sentences.json` มี 30 ประโยคใหม่สำหรับคำเดิมและประโยคกันความหมายตรงตัว:
ผู้ช่วยประเมินว่าใช้ได้ 25 ควรปรับ 2 และความหมายผิด 3
ไม่ได้เป็นการวัดความสามารถกับศัพท์ใหม่ที่ไม่มีในข้อมูลอ้างอิง

สามข้อผิดพลาดใหม่คือไฟลนก้นกระทะจริง การคุยจริงจังเชิงความรัก และผู้พูดขอพักเอง
จึงจำกัดเงื่อนไขการใช้คำอ้างอิง แล้วตรวจใน `context-refinement.json`
พร้อมเพิ่มประโยคเรื่องหม้อและการคุยงบประมาณกับแฟน มี 9 ประโยคที่ความหมายใช้ได้
และอีก 1 ประโยคที่ยังใช้คำอังกฤษไม่เป็นธรรมชาติเรื่องการเลือกคนคุย
รอบ `refinement.json` ยังมีเคสอาหารที่ลดรายละเอียด curry เหลือแค่ cooked ด้วย

`final-verification.json` เป็นการยืนยันเฉพาะ 8 เคสที่เลือกไว้หลังการแก้ล่าสุด:
สามเคสเดิมที่เคยผิด สามเคสใหม่ที่เคยผิด และเคสสมาชิก 50/5 คนกับการทายาแผล
ผู้ช่วยประเมินว่าความหมายใช้ได้ 7 อีก 1 ยังควรเกลาถ้อยคำและการอ้างบุคคล
ดู output จริงและข้อสังเกตที่ [ผลรายประโยค](cases.md)
การทดสอบทุกช่วงเป็นการพัฒนาแบบวนแก้ ไม่ใช่การทดลองเวอร์ชันเดียวตลอดทั้งงาน
เก็บรอบทดลองแรกที่พบตัวตึง/มงลงผิดไว้ใน `exploratory.json` ด้วย

## สิ่งที่เปลี่ยนในระบบ

- เพิ่มข้อมูลภาษาแบบมีบริบท 48 รายการ รวมศัพท์โซเชียล แฟนคลับ เกม
  การละประธาน และคำที่มีทั้งความหมายสแลง/ตรงตัว ระบุเป็น editorial notes
  แยกจากคำจำกัดความของผู้ใช้และแหล่งเผยแพร่ ไม่อ้างว่าฝึกโมเดลหรือทุกคำมีแหล่งยืนยัน
- เลือกเฉพาะข้อมูลคำที่พบ สูงสุดแปดคำต่อช่วง และตัดข้อมูลคำสั้นที่ซ้อนกับวลีเต็ม
  มีเงื่อนไขกันการจับ นอย ใน ฉันอยาก, ขิต ใน ลิขิต และ เมน ใน เมนู/โดเมน
- ใช้ข้อมูลเดียวกันใน Standard, explicit Thai interpretation, semantic review,
  การแปลแต่ละกรอบบนภาพ และผู้ช่วยอธิบาย/ตรวจคำแปล เอกสารกับ Live Chat
  ใช้ตัวแปลกลางและยังคง state/context ของแต่ละฟีเจอร์แยกกัน
- เมื่อข้อมูลภาษาเปลี่ยน cache ของคำแปลภาพ/ข้อความ/คำอ่านจะเปลี่ยน key
  ข้อมูล OCR ยังคงมี cache ของตัวเอง
- ให้ใช้ความหมายธรรมดาเมื่อไม่มีสำนวนอังกฤษที่ตรง รักษาบทบาทผู้พูด/ผู้ฟัง
  และใช้ singular they แทน he/she เมื่อไม่ระบุเพศ
- เพิ่ม flag ตรวจข้อความเสียงสำหรับกลุ่มคำที่ทดสอบพบว่าฟังผิดแม้ segment score ดี
  โดยต้องมีหลายคำชวนสงสัยหรือบริบทแฟนคลับประกอบ ไม่แก้ transcript เอง
- ตัวตรวจตัวเลขเทียบเลขกับคำ cardinal อังกฤษเดี่ยว 0–20 ได้ เช่น 2/two
  ลดการเรียกซ่อมคำแปลเกินจำเป็น ไม่รับส่วนย่อยของ twenty-two, two hundred,
  minus two หรือ two point five และยังคง flag การเปลี่ยน 50 → 5
  นี่ไม่ใช่ parser จำนวนคำทุกภาษา และไม่ตรวจความสัมพันธ์เชิงความหมายได้ทั้งหมด

ข้อมูลความหมายช็อตฟีลตรวจประกอบกับบทความ
[ช็อตฟีล: สำนวนว่าด้วยการเบรกอารมณ์ — The Momentum](https://themomentum.co/wordodyssey-buzzkill/)
ตัวอย่างอังกฤษและเงื่อนไขในแอปเป็นข้อเสนอเชิงบรรณาธิการ ไม่ใช่คำแปลที่ถูกเพียงแบบเดียว

## ภาพ เอกสาร เสียง และภาษาอื่น

- ภาพสังเคราะห์ข้อความไทยสี่กรอบ: Paddle อ่านข้อความทั้งสี่ได้ตรง;
  ป้ายยาหูฟังและกินขาดแปลตามเจตนา รับประกัน 2 ปีแปลได้ ตัวเลข 1,250 คงเดิม
  **แถวราคาถูกเก็บเป็นภาพต้นฉบับทั้งแถว จึงยังมีไทยอยู่** การทดสอบนี้ไม่ได้พิสูจน์
  ว่าแปลทุกคำทับภาพได้หมดหรือเทียบเท่า Google Lens
- เอกสาร TXT สามบรรทัด: ดึงข้อความครบ ไม่เปลี่ยนยังไม่ได้ซื้อเป็นซื้อแล้ว
  รักษา 50 ไม่ใช่ 5 คน และแปลการป้ายยาแผลเป็นการทายา
- เสียง TTS สแลง: Whisper ยังฟัง ด้อม/มือกลอง ผิดเป็น ดอม/มือกล่อง
  หลังเพิ่มการตรวจ ส่งไฟล์เสียงเดิมแล้ว `review_required=true` โดยไม่แก้ข้อความเดิม
  เป็นการลดการส่งข้อความผิดอัตโนมัติ ไม่ใช่ทำให้ ASR ถอดเสียงถูกแล้วทุกคำ
- เสียงอังกฤษ 150 ไม่ใช่ 50 บาทถอด/แปลได้ตรง ส่วนเสียงแพ้ถั่วลิสง
  การสร้างเสียงครั้งแรกไม่สำเร็จ (`NoAudioReceived`) ทดสอบ retry แยกแล้วถอด/แปลได้
  ไม่มีการเพิ่ม retry อัตโนมัติในแอป และไม่ได้ใช้เสียงไมค์จริงหรือเสียงรบกวน
- ชุดใช้งานประจำวันเดิม 16 ประโยค ครอบคลุมต้นทางแปดภาษา ตอบ HTTP 200 ครบ
  เงื่อนไข/ข้อห้าม/เวลา/ยอดเงินหลักยังอยู่ครบจากการอ่านของผู้ช่วย
  มีรายละเอียดภาษาไทยบางจุดควรเกลา เช่น เครื่องหมายวรรคตอนญี่ปุ่นและคำว่าจัดส่ง/ส่งมอบ
  ตัวตรวจซ้ำใช้ไม่ได้ 4 เคส จึงไม่อ้างว่าทั้งหมดผ่าน independent review

ผล feature probes และข้อผิดพลาดจริงเก็บใน `features.json` และ `feature-followup.json`
รูป/TXT/MP3 ในโฟลเดอร์นี้สร้างเพื่อทดสอบ ไม่ใช่ไฟล์ของผู้ใช้

## เวลาและข้อจำกัด

รอบเต็มเดิม median 1.003 วินาที; หลังปรับรอบใหญ่ median 4.430 วินาที
สูงสุด 10.947 วินาที เพราะมีเคสเข้าเงื่อนไขตรวจเพิ่มมากขึ้น
จำนวนไม่เรียก review ลดจาก 79 เหลือ 35 ใน 112 ประโยค เป็นการวัดคนละช่วงเวลา
บนผู้ให้บริการจริงโดยไม่ได้ควบคุมโหลดเครือข่ายหรือ prompt caching
**รอบนี้ความหมายดีขึ้นแต่ช้าลง** การแก้ 2/two ลด repair ที่ไม่จำเป็นในกรณีนั้น
แต่ไม่ได้พิสูจน์ว่า latency รวมกลับมาเร็วเท่าเดิม ไม่มีการวัดค่าใช้จ่ายเงินจริง

ยังจำกัด semantic review ที่ข้อความสั้น 3,000 ตัวอักษร; เอกสารยาวใช้การแบ่งช่วง
และข้อมูลภาษาต่อช่วง แต่ไม่ได้รับการตรวจความหมายเต็มเอกสารแบบไม่จำกัด
บทสนทนากำกวม สแลงใหม่ บริบทประชด รูปตัวเล็ก และเสียงจริงยังต้องมีชุดข้อมูลเพิ่ม
ไม่มีการเทียบ Google รอบนี้ และไม่มีข้อสรุปว่าเก่งกว่า Google Translate

## ตรวจและรันซ้ำ

Backend 182 tests, browser 11 suites, Ruff, frontend syntax และ format checks ผ่าน
ชุดหน้าเว็บยังตรวจ state isolation, ผลลัพธ์เก่าที่มาช้า, การหยุดส่งข้อความไม่แน่ใจ
และการรักษาพิกเซลราคา 50 เมื่อ OCR อ่านเป็น 5

```bash
TRANSLATION_REVIEW_PROVIDER=groq .venv/bin/python -m unittest discover -s tests -q
.venv/bin/python scripts/benchmark_slang_quality.py --live --output reports/slang-upgrade/rerun.json
.venv/bin/python scripts/benchmark_slang_quality.py --live --cases tests/data/slang_new_sentences.tsv --output reports/slang-upgrade/new-rerun.json
.venv/bin/python scripts/benchmark_feature_quality.py --live --output reports/slang-upgrade/feature-rerun.json
```

คำสั่ง `--live` ใช้โควตาบริการจริง Benchmark slang ต้องเปิด app.py อยู่ด้วย
ผลใหม่อาจต่างจากเดิม เกณฑ์และข้อสังเกตอยู่ใน `assessment-notes.json`
hash ส่วน runtime ที่ใช้ช่วงยืนยันสุดท้ายอยู่ใน `final-manifest.json`
