## ส่วนที่ตรวจ

- ข้อความ: ข้อมูลคำขอ ภาษา Style ทั้ง 6 แบบ บริบท การแบ่งข้อความยาว แคช แปลเพิ่มเติมหลายภาษา และข้อผิดพลาดจากผู้ให้บริการ
- เอกสาร: อ่านไฟล์ TXT/MD/CSV/DOCX/PDF จริงในชุด Python ลำดับย่อหน้า/ตาราง PDF สแกน ขีดจำกัดไฟล์ และไฟล์เสียหาย
- รูปภาพ: HEIC/HEIF และ EXIF, OCR, ภาษาปนกัน การเก็บตัวเลขเดิม การแสดงและส่งออก PNG สถานะ 429 การลองใหม่ ยกเลิก และผลตอบกลับที่มาช้า
- เสียง: จับเสียงใน Chromium ด้วยเสียงจำลอง ตรวจความเงียบ ตรวจข้อความก่อนส่ง การเทียบคำถอดเสียง เสียงอ่านสำรอง การยกเลิก และคืนทรัพยากรไมค์เมื่อเปลี่ยนโหมด
- Live Chat: บริบทบทสนทนา การถามยืนยันความหมาย ข้อความที่ยังไม่ส่ง และการแยกข้อมูลแต่ละฟีเจอร์
- ผู้ช่วย: คำอ่าน Why this?, Check translation, Deep review, คลังคำ วิเคราะห์/เปรียบเทียบ แนะนำ 3 คำตอบ คัดลอก ฟังเสียง และ Edit first
- เมนู/หน้าจอ: Style/Context ประวัติ รายการโปรด ธีม ภาษาเมนู การแจ้งเตือน 3 วินาที คีย์บอร์ด ภาษา RTL และขนาดมือถือ/แท็บเล็ต/เดสก์ท็อป
- การเริ่มระบบ: import Flask และ dependencies, API จริงใน process ที่กำลังรัน, static assets และขั้นตอนเตรียมไฟล์สำหรับ Vercel

ชุดเบราว์เซอร์ใช้ Chromium ส่วนใหญ่จำลองคำตอบ AI/เสียง เพื่อควบคุมกรณีสำเร็จ ล้มเหลว และคำตอบที่มาช้า ส่วน validation/audit บางจุดเรียก backend จริง ไม่ใช้ผลเหล่านี้อ้างความแม่นยำของ AI

## สิ่งที่พบและปรับ

1. `semantic-review.cjs` ยังรอข้อความ “could not be completed” ที่ผู้ใช้สั่งเอาออกแล้ว ทำให้ทดสอบ timeout ปรับให้ยืนยันว่าคำแปลยังแสดงอยู่ สถานะ `unavailable` ยังเก็บในข้อมูล และไม่มีข้อความแจ้งแปลเสร็จ รวมทั้งยังตรวจว่าข้อความที่ต้องถามความหมายไม่ถูกส่งหรือบันทึก
2. เพิ่ม `runtime-contract.cjs` เข้า `npm run test:browser` ให้ส่งคำขอผ่าน backend จริงครบ Standard/Natural/Formal/Casual/Friendly/Business แบบภาษาเดียวกัน จึงไม่ใช้โควตา AI และตรวจพบกรณี Flask เก่ายังปฏิเสธค่าเมนูใหม่ได้ ปัญหานี้ได้รับการแก้โดยรีสตาร์ตเซิร์ฟเวอร์ในงานก่อนหน้า
3. ปรับคำอธิบาย README ให้ตรงกับพฤติกรรมที่เอาข้อความแจ้งแปลเสร็จออกแล้ว

ไม่พบข้อผิดพลาดของโค้ดแอปที่ทำให้กรณีทดสอบข้างต้นใช้งานไม่ได้ในรอบนี้

## ทดสอบบริการจริง

ผลดิบ: [live-smoke.json](live-smoke.json) ใช้ข้อความ รูป และไฟล์เสียงตัวอย่างของโครงการ ไม่มีคีย์ API ในรายงาน

| ส่วน | ผลจริง |
| --- | --- |
| หน้าเว็บ รายชื่อภาษา แค็ตตาล็อก และสถานะ OCR | HTTP 200 |
| แปล Standard และ Business | HTTP 200 มีคำแปล |
| คำอ่าน อธิบาย ตรวจคำแปล Suggest 3 replies | HTTP 200 ทั้ง 4 แบบ มีคำตอบสองภาษาครบ 3 แบบ |
| Deep review และเปรียบเทียบคำแปล | HTTP 200 |
| Live Chat | ได้คำแปล HTTP 200; การตรวจความหมายครั้งแรก unavailable ภายหลังลองใหม่ได้ checked |
| อ่านเอกสาร TXT | HTTP 200 ข้อความครบ |
| แปลเอกสาร | ครั้งแรก HTTP 429 หลังรอแล้วลองใหม่ HTTP 200 |
| Preview รูป | HTTP 200 เป็น PNG |
| แปลรูป | ครั้งแรก HTTP 429 หลังรอแล้วลองใหม่ HTTP 200 ครบ 4 พื้นที่ ไม่มีอักษรไทยหลงเหลือในคำแปลอังกฤษ และคง 1,250 / 2 ไว้ |
| เสียงอ่านอังกฤษและไทย | HTTP 200 ได้ MP3 ขนาด 11,232 / 11,808 bytes |
| ถอดเสียงตัวอย่างไทย | HTTP 200 แต่ถอดสแลงผิด ระบบส่ง `review_required: true` |

ข้อจำกัดที่ยังพบจริง:

- โควตาผู้ให้บริการ AI ยังทำให้เกิด 429 ได้ รอบนี้ตอบ `retry_after: 2` และลองใหม่ภายหลังสำเร็จ ไม่สามารถสรุปว่าปัญหาโควตาหายถาวร
- ตัวอย่างเสียงต้นฉบับ “ฉันอยู่สองด้อม เมนของฉันคือมือกลอง” ถูกถอดเป็น “ฉันอยู่ 2 ดอมเมนของฉันคือมือกล่อง” ระบบติดธงให้ตรวจข้อความแล้ว แต่ยังไม่สามารถอ้างว่าถอดสแลงได้ถูกต้องทั้งหมด
- เสียงอ่านสำเร็จในรอบนี้ ไม่ใช่หลักประกันว่าบริการภายนอกจะไม่เกิด NoAudioReceived อีก
- ไม่ได้ทดสอบไมค์จริง สำเนียง เสียงรบกวน กล้องจริง Safari/iOS หรือ Android เครื่องจริง ไม่ได้วัดความแม่นยำทุกภาษา และไม่ได้ตรวจ production deployment

## คำสั่งทดสอบ

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/ruff check .
.venv/bin/ruff format --check .
npm run check
npm run format:check
.venv/bin/python -m pip check
TRANSLATOR_TEST_URL=http://127.0.0.1:5001 npm run test:browser
.venv/bin/python scripts/build_vercel.py
```

เครื่องนี้ต้องตั้ง `LD_LIBRARY_PATH=/tmp/translator-browser-libs/extracted/usr/lib/x86_64-linux-gnu` สำหรับ Chromium ด้วย ชุดเบราว์เซอร์รอบแรกหยุดที่ semantic-review จึงรันชุดนั้นหลังแก้และรันชุดที่เหลือแยกจนครบ 20 ชุด จากนั้นรัน runtime-contract ที่เพิ่มใหม่ ผลผ่านทั้งหมด ไม่ได้นับเฉพาะชุดก่อนจุดที่หยุด
